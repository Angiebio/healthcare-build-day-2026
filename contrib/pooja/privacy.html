Privacy & compliance

What we implemented, what we deliberately did not claim, and how to check both.

What we claim

Lantern implements a de-identification pipeline aligned to DICOM PS3.15, the standard's Attribute Confidentiality Profiles, with policy-gated release evidence attached to every record.

Each Study Passport ships with a de-identification manifest stating exactly what was removed, what was generalized, and what was replaced with a consistent pseudonym. The evidence travels with the data, so a receiving privacy office can audit the transformation rather than trust a description of it.

What we deliberately do not claim

Lantern is not described as HIPAA compliant, and that omission is intentional. Under the Privacy Rule, de-identification is established by one of exactly two routes: Safe Harbor, which requires removal of all eighteen enumerated identifier categories, or Expert Determination, which requires a qualified statistician to document that re-identification risk is very small. Neither is achievable in a five-hour prototype, and a system asserting otherwise should not be trusted with a child's imaging.

Even properly de-identified data retains residual re-identification risk. Any real deployment would require formal determination, institutional review, and a data use agreement appropriate to the release layer.

A privacy claim that cannot be audited is not a privacy claim. We would rather state a narrower thing we can evidence than a broader thing we cannot.

Why small cohorts are the hard case

In pediatric and rare disease research, scientific value and re-identification risk rise together. The cohorts that most need to be found are the ones most easily identified. A hospital reporting that it holds exactly one child with a given rare condition may have disclosed that child.

Lantern therefore suppresses results below a configurable threshold, returning an approximate count and a petition pathway instead of records. The threshold is not hidden inside the system — it is returned in the API response so that any consumer can see the rule being applied to them.

Suppression alone is insufficient, because an attacker can approach a protected count by asking two nearly identical questions and subtracting. Lantern fingerprints queries and detects that pattern, degrading precision when a sequence of requests would isolate a small group.

Data used

No real patient data was used at any stage. All records in this demonstration are synthetic, supplied as part of the challenge. Any patient names visible in the raw source data are fictional, and the pipeline removes them regardless.

Verifying these claims

The source is public and MIT licensed. The de-identification logic, the disclosure guard, and the suppression threshold are plain, tested functions rather than model behavior — deliberately, so they can be read, tested, and disproven. Every control described on this page corresponds to code you can inspect and a test you can run.
